## Why

Пользователь помнит, что произошло с заказом или поездкой, но забыл тему письма. Цель — открыть нужное письмо по описанию события, сохранив возможность искать по точным номерам и именам.

## What Changes

- Прототип почты с просмотром писем, строкой поиска и открытием результата.
- Два способа найти письмо-кандидат. BM25 учитывает совпадения слов и номеров. Локальный энкодер сопоставляет смысл запроса с заранее рассчитанными векторами писем. Первый эксперимент объединяет списки по позициям (RRF).
- Демо для обсуждения. На примере «самолёт улетит позже» открыть письмо с новым временем вылета, затем найти его по номеру брони. Пример иллюстративный. Перед защитой выбрать реальные запросы и письма из корпуса.
- Варианты для сравнения на одних запросах — BM25, только энкодер, гибрид. Гибрид — рабочая гипотеза. Более сложное повторное ранжирование имеет смысл обсуждать после разбора ошибок и замера задержки.

## Capabilities

### New Capabilities

- `mail-search` — поиск в выбранном ящике, просмотр результатов и воспроизводимая оценка выдачи.

## Impact

В main уже есть корпус из 16 376 писем, 99 запросов, 565 связей релевантности, BM25, веб-интерфейс и экспорт выдачи. ML подбирает модель, бэкенд готовит запуск инференса. Первой совместной поставкой будет один сквозной запрос через существующий интерфейс и тот же поиск в бенчмарке.

## Основание для выбора модели

На коммите `35379d8` команда `python3 -m mail_search benchmark --limit 10` дала Recall@10 0,9249 и nDCG@10 0,9785 по 99 запросам. MRR@10 составил 1,0000 на 42 запросах с одним релевантным письмом. В одном последовательном локальном прогоне p99 вызова поиска составил 363,64 мс. Серверный p99 под нагрузкой ещё предстоит измерить.

Для 15 запросов размечено больше десяти релевантных писем. Поэтому потолок среднего Recall@10 на этих данных равен 0,9376 (среднее min(10, число релевантных) / число релевантных). Запас роста BM25 составляет около 1,27 процентного пункта. Только на пяти запросах число найденных релевантных писем меньше достижимого при K=10. Три касаются электронных чеков, ещё два — погрузки контейнеров и прибытия автомашин. На остальных запросах модель всё ещё может изменить порядок выдачи.

Гипотеза ML — повысить устойчивость к пересказу своими словами при сохранении точных дат и идентификаторов. Показательный запрос для диагностики — письма с электронными чеками за 1 октября 2028 года: BM25 нашёл четыре из двенадцати размеченных при десяти доступных местах. Сначала выяснить, где потерялись остальные: фильтр даты, отбор кандидатов или ранжирование. Это определяет следующий эксперимент.

## Решение после интеграции

Оставляем гибрид, если он исправляет конкретные ошибки или помогает на заранее отложенных перефразировках, сохраняет качество на точных запросах и проходит серверный p99 < 1 с. При спорном размене показываем команде изменившиеся ранги и задержку. Если модель не даёт измеримого выигрыша, сохраняем BM25 для демо. Следующую модель выбираем под повторяющийся тип промаха. Дообучение рассматриваем при наличии отдельных обучающих примеров и независимой проверки.
