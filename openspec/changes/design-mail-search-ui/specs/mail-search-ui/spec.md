# Фронтенд поиска по почте · черновик для согласования

Пользователь помнит событие и хочет открыть подтверждающее письмо. Критерий успешного демо — пользователь своими словами вводит запрос, понимает, за какой день показаны результаты, и находит подтверждение в тексте письма.

## Схема экрана и переходов

```text
Контекст демо     [Почтовый ящик ▾]  [Дата отсчёта]
Поиск             [Найди электронные чеки за вчера       ] [Найти]
Выдача            Найдено в выдаче: N · За <день, определённый сервером>
┌────────────────────────────┬────────────────────────────────┐
│ Тема · дата                │ Тема выбранного письма         │
│ Фрагмент письма            │ Дата                           │
│ Следующий результат        │ Полный текст                   │
└────────────────────────────┴────────────────────────────────┘
```

При входе пустая строка показывает последние письма. На широком экране список остаётся рядом с письмом. Для узкого экрана предлагаем переход из списка в письмо и кнопку «К результатам», которая сохраняет запрос, день, выделение и позицию прокрутки.

## Требования и приёмка

| Приоритет | Что видит пользователь | Как принимаем |
| --- | --- | --- |
| P0 · Контекст | Ящик и дата отсчёта доступны до поиска | Смена ящика обновляет дату по умолчанию и выдачу. Открытое ранее письмо исчезает. |
| P0 · Поиск | Одна строка, запуск кнопкой или Enter | Результаты идут в порядке API. Количество относится к полученной выдаче. Очистка и отправка строки возвращает последние письма. |
| P0 · Время | Для «за вчера» рядом с выдачей указан календарный день | День берётся из X-Target-Day. Например, при дате отсчёта 02.10.2028 и ответе 2028-10-01 показываем «За 1 октября 2028». Без заголовка подпись скрыта. |
| P0 · Чтение | В списке видны тема, дата и фрагмент, при выборе — полный текст | Открывается выбранный doc_id в том же ящике на ту же дату. Пустая тема и неизвестная дата имеют понятные подписи. Текст письма отображается как текст. |
| P0 · Состояния | Различимы загрузка, пустой ящик, пустая выдача, ошибка и резервный поиск | При пустой выдаче можно изменить запрос. При сбое сети или 503 доступен повтор без потери ввода. При 404 письма список доступен. При bm25-fallback показана выдача с пометкой «Поиск по словам». |
| P0 · Последний запрос | Быстрая смена запроса или ящика сохраняет актуальный контекст | Задержанный ответ предыдущего поиска или открытия письма игнорируется. |
| P1 · Навигация | Поиск и чтение доступны с клавиатуры и на узком экране | Видимый фокус, Enter открывает выбранный результат. На ширине 360 px основные действия доступны без горизонтальной прокрутки. |

## Что уже есть и где нужна работа

В main на c767e20 есть форма, список, чтение письма, подпись целевого дня, индикация резервного режима и защита от устаревших ответов. Фронтенд уже получает всё для основного сценария через GET /api/mailboxes, /api/search и /api/message. В доработку предлагаем локализацию даты, раздельные пустые состояния, явный повтор после ошибки и возврат к результатам на телефоне.

## Решения для ревью

1. Принимаем двухпанельный экран на ноутбуке и отдельное чтение письма на телефоне?
2. Оставляем выбор ящика и даты видимым в контексте демо? Это позволяет воспроизвести запрос из бенчмарка.
3. Для первой версии предлагаем согласовать только поиск и чтение. Подборку чеков за день из продуктового плана оценим отдельно после проверки главного сценария.
