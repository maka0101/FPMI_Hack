# Spec Delta

## Purpose

Помогает найти письмо по его близости к знакомому событию в том же почтовом ящике. Пользователь сам выбирает письмо, дату которого поиск использует как ориентир.

## ADDED Requirements

### Requirement: Выбор письма-ориентира

Веб-интерфейс SHALL показывать рядом со строкой поиска действие «Помню, что было рядом». Оно открывает форму «Какое письмо вы помните?», сохраняя основной запрос. По непустому запросу форма SHALL показать до трёх ранжированных кандидатов с известной датой из текущего ящика на выбранную дату отсчёта.

#### Scenario: По запросу найдено несколько кандидатов

- **WHEN** поиск по описанию ориентира находит несколько доступных писем
- **THEN** интерфейс показывает тему, дату и отправителя каждого кандидата, если отправитель известен
- **AND** пользователь сам выбирает письмо, затем одно из направлений «После него», «До него» или «Примерно тогда же»

#### Scenario: Подходящих ориентиров нет

- **WHEN** среди доступных писем с датой нет кандидатов
- **THEN** форма сообщает об этом, сохраняет основной запрос и позволяет уточнить описание ориентира

### Requirement: Границы доступности и окна

Сервис SHALL определять дату по идентификатору ориентира, доступного в текущем ящике на дату отсчёта. Окно по умолчанию охватывает X = 3 календарных дня в выбранном направлении. Сервис SHALL учитывать только письма с датой в этом окне из того же ящика и исключать сам ориентир.

#### Scenario: Поиск с заданным направлением

- **WHEN** дата ориентира равна D
- **THEN** «После него» использует дни от D+1 до D+X, «До него» от D−X до D−1, а «Примерно тогда же» от D−X до D+X, включая крайние дни
- **AND** верхняя граница ограничена датой отсчёта, а при указанном в основном запросе периоде действует пересечение обоих условий
- **AND** пустое пересечение даёт пустую выдачу

#### Scenario: Ориентир недоступен

- **WHEN** выбран неизвестный идентификатор, письмо из другого ящика, письмо позже даты отсчёта или письмо без даты
- **THEN** сервис сообщает, что ориентир недоступен, и предлагает выбрать письмо заново

### Requirement: Ранжирование внутри окна

При текстовом запросе сервис SHALL возвращать до десяти результатов, ранжируя допустимые письма действующим гибридным поиском. При равном итоговом балле SHALL первым идти письмо, ближайшее по дате к ориентиру, затем письмо с меньшим идентификатором.

#### Scenario: Нужное письмо отсутствует в глобальной выдаче

- **WHEN** письмо входит в десятку лучших внутри окна, но отсутствует в обычном топ-10
- **THEN** оно появляется в выдаче поиска по ориентиру

#### Scenario: Просмотр писем по близости к ориентиру

- **WHEN** пользователь применяет ориентир при пустом основном запросе
- **THEN** сервис показывает до десяти допустимых писем от ближайших к более далёким, при равной дистанции по идентификатору письма

### Requirement: Пояснения и чтение писем

Интерфейс SHALL показывать над выдачей применённое условие с темой ориентира, направлением и размером окна. В каждой карточке SHALL быть видна разница календарных дат со знаком направления. При открытии карточки SHALL использоваться существующая панель чтения.

#### Scenario: Письма получены в соседние дни

- **WHEN** результат получен на следующий календарный день после ориентира
- **THEN** карточка показывает «На следующий день»
- **AND** для результата с датой ориентира интерфейс использует подпись «В тот же день»

#### Scenario: В окне из трёх дней пусто

- **WHEN** поиск успешно завершился и не вернул писем в окне из трёх дней
- **THEN** интерфейс предлагает «Расширить до 7 дней»
- **AND** при выборе действия сохраняет ящик, дату отсчёта, основной запрос, ориентир и направление, пересчитывая окно с X = 7

#### Scenario: Контекст меняется во время поиска

- **WHEN** пользователь меняет ящик или дату отсчёта либо снимает условие по ориентиру
- **THEN** интерфейс сбрасывает выбранный ориентир и снова позволяет выполнить обычный поиск
- **AND** запоздавший ответ по прежнему условию не меняет текущую выдачу
