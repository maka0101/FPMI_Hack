# Design

## Context

`MailboxIndex` хранит письма в SQLite и выполняет BM25 через FTS5. `Engine.search_with_info` объединяет результаты BM25 и ML через взвешенное RRF. Профиль `harrier270` использует веса 0,85 и 0,15. В текущей рабочей копии обе ветви поддерживают `DateRange` до отбора кандидатов, а ML принимает его в `target_range`. На этой поддержке строится изменение.

`doc_dt` есть у 15 943 из 16 376 писем корпуса. Все известные значения имеют точность до дня. В архиве нет отдельного поля отправителя. Часть писем хранит его в размеченной шапке, которую текущий интерфейс уже умеет читать при открытии письма. Основной поиск, выбор ящика, дата отсчёта и панель чтения живут в `mail_search/index.html`.

## Goals / Non-Goals

**Goals**

- Использовать текущий движок, индексы и API чтения. Передать в BM25 и ML одинаковые ограничения на допустимые письма.
- Сохранить контракт и порядок обычного поиска, включая вызовы CLI и бенчмарка.

**Non-Goals**

- MVP работает с календарными датами из индекса. Поиск по часам требует источника времени получения.
- Ввод одной фразой можно добавить позже поверх того же контракта выбора ориентира и направления.

## Decisions

### Веб-контракт

- `GET /api/search/anchors?mailbox=…&as_of=…&q=…` возвращает массив из максимум трёх карточек кандидатов с `doc_id`, `subject`, `day` и nullable `sender`. Поиск переиспользует текущий движок. Ограничение на известную дату применяется до ранжирования, чтобы письма без даты не вытесняли пригодные ориентиры. Отправитель и недостающая тема извлекаются из последовательных размеченных строк в начале полного текста, по тем же правилам, что в панели чтения. В интерфейсе пустые значения получают подписи «Без темы» и «Отправитель неизвестен».
- `GET /api/search/around?mailbox=…&as_of=…&q=…&anchor_doc_id=…&direction=…&days=…` принимает `before`, `after` или `around`. `days` равен 3 по умолчанию и принимает 7 при расширении. Ответ содержит карточку `anchor`, фактический диапазон `window` (или `null` при пустом пересечении) и `results` с полями обычной карточки и знаковым `offset_days`. Фактический режим поиска передаётся в `X-Search-Mode`.
- Backend разрешает `anchor_doc_id` через тот же ящик и дату отсчёта, что и чтение письма. Для неизвестного, чужого, будущего и недатированного ориентира возвращается одинаковый 404 «Письмо-ориентир недоступно». Некорректные параметры дают 400. Сбой ML даёт 503, а явно включённый резервный режим при таймауте использует тот же диапазон.


Для интеграции передавайте один и тот же `mailbox` и `as_of` во все запросы сценария. Если `as_of` опущен, сервер применяет обычную дату отсчёта ящика. В первом запросе `q` описывает ориентир, а во втором содержит основной поисковый запрос. Пустой `q` во втором запросе включает просмотр по близости.

`window` содержит включительные границы `start` и `end` в формате `YYYY-MM-DD`. В `results` у каждой карточки есть `doc_id`, `subject`, `day`, `preview` и `offset_days`. Отрицательное смещение обозначает письмо до ориентира, нулевое — тот же день, положительное — письмо после ориентира. Для расширения окна повторите запрос с `days=7`. Для чтения письма используйте существующий `GET /api/message` с `doc_id` результата.

### Окно и ранжирование

1. Backend вычисляет диапазон на основе даты письма и выбранного направления. Дни до и после начинаются с соседнего календарного дня, а «Примерно тогда же» включает день ориентира. Границы включительные. Диапазон пересекается с датой отсчёта и календарным фильтром из основного запроса. Пустое пересечение сразу возвращает пустой список.
2. Движок передаёт эффективный период в `MailboxIndex.search_parsed`, `MLClient.candidates` и проверку метаданных семантических кандидатов. Для BM25 исключить `anchor_doc_id` в SQL. Если день ориентира попадает в период, запросить у ML на одного кандидата больше и удалить ориентир до восстановления глубины и расчёта рангов. В MVP итоговая выдача фиксирована до десяти, поэтому с глубиной кандидатов 50 дополнительная строка укладывается в лимит протокола. Временной фильтр действует до отбора топ-кандидатов в каждом списке.
3. Для текстового запроса сохранить текущие веса и добавить расстояние до ориентира в ключ финальной сортировки при равном RRF-балле, перед `doc_id`. Backend вычисляет знаковое смещение как разность календарных дат. Для пустого запроса брать письма по абсолютному смещению и `doc_id` внутри окна, применяя лимит после этой сортировки. Просмотр без текста обходится одним обращением к SQLite.

### Состояние интерфейса

Форма хранит описание ориентира, выбранный `doc_id`, направление и размер окна. Выбор меняет выдачу на том же экране. Чип над результатами показывает, например, «Новый заказ · в течение 3 дней после письма “Новый возврат…”». Для карточки используются «На следующий день», «За 2 дня до» и «В тот же день» по данным API. При пустом результате кнопка расширяет диапазон один раз. При недоступном ориентире форма предлагает выбрать его заново, а при сетевой ошибке сохраняет ввод для повтора. Смена ящика или даты сбрасывает выбор и инвалидирует ожидающие ответы. Существующая панель получает исходные `mailbox`, `as_of` и `doc_id` при открытии письма.

## Risks / Trade-offs

- Архив может содержать время покупки, отправки заказа или другой операции внутри текста. Для направления и подписи используется только дата получения `doc_dt`, чтобы такие времена не влияли на выдачу.
- Фильтрация глобального топ-10 может скрыть письма, доступные внутри окна. Приёмочный тест должен поместить целевое письмо ниже глобальной десятки и проверить обе ветви отбора кандидатов.
- У ориентира и у поиска внутри окна независимые ошибки и задержки. Интерфейс сохраняет ввод для повтора, а замеры фиксируют задержку каждой операции отдельно.

## Проверка на корпусе до UI

Локально использованы исходный корпус хакатона и готовый индекс Harrier 270M. Обычный запрос и поиск кандидатов для ориентира прошли через `Engine.search`. Для контрольной выдачи передали один и тот же `DateRange` в текущие BM25 и `/v1/candidates`, затем объединили их штатным RRF. Это воспроизводит отбор в окне для направления «После него».

| Параметр | Значение |
| --- | --- |
| Ящик и дата отсчёта | `box-f9410417c091`, 2028-12-18 |
| Запрос для ориентира | «возврат АвтоДело» |
| Выбранное письмо | «Новый возврат…», `L-eb4e7468b86367e6a474`, 2027-11-30, №2 из 3 кандидатов |
| Основной запрос | «новый заказ» |
| Целевое письмо | «Есть новый заказ», `L-f2842118c7388426ae5f`, 2027-12-01 |
| Обычный поиск | Цели нет в топ-10 |
| Три дня после ориентира | 2027-12-01 — 2027-12-03 включительно, цель №1 из 7 |

Цель выбрана для демонстрации, поэтому этот пример показывает эффект фильтра на конкретном письме. Для приёмки повторить сравнение через новые веб-операции и проверить открытие письма в панели.

## Проверка API и пробная интеграция

При пробной интеграции в Chrome с локальным Harrier 270M результат воспроизвёлся. Итоговая интеграция интерфейса проверяется в отдельной ветке. Цель отсутствовала в обычной десятке, заняла первое место из семи в окне и открылась в штатной панели чтения. Проверены условие над результатами, подписи «На следующий день» и «В тот же день», расширение окна, выбор с клавиатуры и отклонение запоздавшего ответа после смены даты.

В этом единичном прогоне `Server-Timing` показал 82,2 мс для поиска ориентира и 22,6 мс для поиска в окне. На 99 публичных запросах порядок обычной выдачи совпал до и после изменения на том же индексе Harrier 270M.
