# Умный поиск в Почте

Прототип для кейса VK Tech. В репозитории лежат [данные участников](mipt_mail_search_participants/README.md), поисковый движок и веб-интерфейс для поиска и просмотра писем.

Для запуска нужен Python 3.9+ со встроенным SQLite FTS5. BM25 работает без дополнительных пакетов и модели.

```sh
python3 -m mail_search serve
```

Откройте [локальный интерфейс](http://127.0.0.1:8000). Выберите почтовый ящик, задайте дату отсчёта и введите запрос. Пустой запрос показывает последние доступные письма. Для запроса «электронные чеки вчера» день получения вычисляется относительно выбранной даты.

Движок строит индекс в памяти при запуске и ранжирует результаты по BM25 с повышенным весом темы. Для русских слов он учитывает точную форму и совпадения по префиксу. Поиск ограничен выбранным ящиком и исключает письма, полученные после даты отсчёта. Поддерживаются «сегодня», «вчера», «позавчера» и конкретные даты. При поиске за конкретный день письма без даты не попадают в выдачу.

## Гибридный поиск

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt

mkdir -p .cache/e5-model
curl -fsSL https://huggingface.co/Xenova/multilingual-e5-small/resolve/main/tokenizer.json \
  -o .cache/e5-model/tokenizer.json
curl -fsSL https://huggingface.co/Xenova/multilingual-e5-small/resolve/main/onnx/model_quantized.onnx \
  -o .cache/e5-model/model_quantized.onnx

python -m mail_search serve --model-dir .cache/e5-model
```

При первом запуске сервис кодирует письма на CPU локальной ONNX-версией `multilingual-e5-small`. Сохраняется один нормализованный вектор на письмо с учётом темы и тела, до 512 токенов. При следующих запусках эмбеддинги загружаются из `.cache/e5-embeddings.npz`. Изменение текстов, модели или токенизатора приводит к пересчёту. После скачивания весов поиск работает без сети.

Для каждого запроса дата извлекается из текста. Движок ограничивает почтовый поиск выбранным ящиком и допустимыми датами до отбора первых 50 кандидатов (или больше, если запрошен больший лимит). Векторная ветка ранжирует допустимые письма по косинусной близости к русскоязычному запросу. RRF объединяет списки с равными весами и константой 60. При равенстве итоговых оценок впереди кандидат из списка BM25. Для чистого BM25 и двухветочного гибрида `/api/search` принимает соответственно `mode=bm25` и `mode=hybrid`.

## Публичный бенчмарк

```sh
python3 -m mail_search benchmark --limit 10 --output rankings.jsonl
```

Команда прогоняет BM25 с ящиком и датой из каждого запроса. Она печатает Recall@K и nDCG@K по размеченным запросам, MRR@K по запросам с одним релевантным письмом и p99 времени вызова поиска без HTTP и индексации. Флаг `--output` сохраняет по одной строке JSON на запрос с полями `query_id` и `doc_ids` в порядке выдачи.

Для сравнения двух режимов через `/api/search` используйте следующую команду.

```sh
python -m mail_search compare --model-dir .cache/e5-model --repeats 5 \
  --output /tmp/vk-mail-search-results.json
```

Бенчмарк отправляет 99 исходных запросов и 99 [парных перефразировок](benchmarks/paraphrases.jsonl). Перефразировки сделаны вручную по 12 группам запросов с сохранением ящика, дня и `query_id`, поэтому для них используются исходные оценки релевантности. После прогрева запросы выполняются по одному в перемешанном порядке. Сервер считает задержку с разбора HTTP-запроса до сериализованной выдачи, включая обработку запроса, инференс и ранжирование. Запуск, индексация и передача ответа клиенту в этот замер не входят. При пяти повторах p99 рассчитан по 495 вызовам каждой комбинации набора запросов и режима.

[Результаты](benchmarks/results.json) получены на Apple M4 Pro с ONNX INT8 на CPU.

## Сравнение моделей

Кандидаты в ветке `ML` запускаются из локальных весов. Для PyTorch-кандидатов используйте Python 3.10+ и `requirements-ml.txt`.

```sh
python -m pip install -r requirements-ml.txt
python -m mail_search.download_models all
python -m mail_search serve --embedder granite97
python -m mail_search serve --embedder granite97 --reranker ru-reranker
```

Энкодер выбирается через `--embedder e5|granite97|user2-small|harrier270`, ранжировщик — через `--reranker ru-reranker|bge-reranker`. Параметр `--device cpu|mps|cuda` позволяет задать устройство PyTorch. По умолчанию сервис использует доступный GPU, а при его отсутствии CPU. У E5 остаётся исходный ONNX на CPU. Для остальных моделей отдельные кэши формируются при первом запуске. С установленным ранжировщиком обычный `/api/search` применяет его к первым 20 кандидатам RRF. Чтобы посмотреть выдачу до ранжировщика, передайте `mode=hybrid`.

```sh
python -m mail_search compare --embedder granite97 --repeats 3 --include-undated
python -m mail_search compare --embedder granite97 --reranker ru-reranker \
  --repeats 3 --include-undated --output benchmarks/ml-granite-ru.json
```

Параметр `--include-undated` убирает день из перефразировок, сохраняя ящик и дату отсчёта. Для этих запросов отчёт показывает полноту по исходным известным целевым письмам. Другие письма на тот же сюжет могут тоже быть релевантны. Для сравнения ранжировщиков отчёт сохраняет SHA-256 упорядоченных top‑20 по каждому запросу. [Модели и методика эксперимента](benchmarks/models.md)

## Длинные запросы и расширенная проверка

Сервис принимает до 4 000 символов. Для длинного запроса отдельная векторная ветка получает выжимку цели поиска. Правила выбирают фразу запроса и явные уточнения из исходного текста. Короткие запросы и запросы с точным кодом, номером или суммой сохраняют двухветочный поиск. Обе векторные ветки используют один энкодер и один набор разрешённых писем. RRF объединяет три списка, если выжимка сгенерировала отдельный список кандидатов. При подключённом ранжировщике он получает top‑20 после RRF и исходный запрос без выделенной даты.

По умолчанию гибрид использует `mode=hybrid-summary`, с ранжировщиком — `mode=hybrid-summary-rerank`. Для контрольного поиска из двух веток есть `hybrid` и `hybrid-rerank`. Режимы `hybrid-summary-raw` и `hybrid-summary-raw-rerank` оставляют третий голос и для точных запросов.

```sh
python -m benchmarks.build_expanded
python -m mail_search evaluate-expanded --embedder harrier270 --output /tmp/harrier-expanded.json
```

Команда сопоставляет защищённый и исходный гибрид. Флаг `--raw-summary` проверяет третий голос без защиты. Расширенная разметка и общая методика находятся в [отчёте](benchmarks/expanded/README.md).
