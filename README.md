# Умный поиск в Почте

Прототип для кейса VK Tech. В репозитории лежат [данные участников](mipt_mail_search_participants/README.md), поисковый движок и веб-интерфейс для поиска и просмотра писем.

Для локального запуска нужны uv и Python 3.11 со встроенным SQLite FTS5. По умолчанию сервис работает в режиме BM25.

```sh
uv sync --locked --python 3.11
MAIL_SEARCH_FRONTEND_V2=1 uv run --locked python -m mail_search serve
```

Откройте [локальный интерфейс](http://127.0.0.1:8000). Выберите почтовый ящик, задайте дату отсчёта и введите запрос. Пустой запрос показывает последние доступные письма. Для запроса «электронные чеки вчера» день получения вычисляется относительно выбранной даты.

Движок строит индекс в памяти при запуске и ранжирует результаты по BM25 с повышенным весом темы. Для русских слов он учитывает точную форму и совпадения по префиксу. Поиск ограничен выбранным ящиком и исключает письма, полученные после даты отсчёта. Поддерживаются «сегодня», «вчера», «позавчера» и конкретные даты. При поиске за конкретный день письма без даты не попадают в выдачу. Это лексический baseline, который может пропускать перефразировки без совпадений слов.

## Локальное демо интерфейса v2

```sh
MAIL_SEARCH_FRONTEND_V2=1 uv run --locked python -m mail_search serve
```

Откройте [v2 с демоданными](http://127.0.0.1:8000/v2?demo=1). Начните вводить «Смета на ремонт». В появившемся под поиском поле «Помните, что было примерно в это время?» введите «после покупки билетов в Казань». Дождитесь подсказок и выберите билет от 12 мая. Выдача сразу сузится до выбранного периода. Из неё можно открыть почту вокруг события. Из последних писем можно открыть хронологию через «Посмотреть почту вокруг события». Панель также принимает даты, например «10–12 мая 2026».

Для обычного поиска по корпусу выберите «Почтовый API». Для новой панели в этом режиме нужны операции из [спецификации бэкенда и ML](docs/event-recall-backend-ml.md). Если API пока их не поддерживает, панель предложит демоданные.

Чтобы проверить неоднозначный запрос, найдите «Документы готовы к подписанию». Нажмите Enter, чтобы увидеть два письма с одинаковой темой и текстом от 31 марта и 14 мая. Подсказка «после просмотра квартиры на Парковой» ведёт к письму от 31 марта, а «после предложения о работе по аналитике» — к письму от 14 мая. В хронологии каждое письмо видно рядом со своим ориентиром.

V2 доступен на `/` и `/v2` при `MAIL_SEARCH_FRONTEND_V2=1`. Для локальной проверки старого интерфейса задайте `MAIL_SEARCH_FRONTEND_V1=1` и откройте `/v1`. На сервере оставляйте v1 выключенным.

## Публичный бенчмарк

```sh
uv run --locked python -m mail_search benchmark --limit 10 --output rankings.jsonl
```

Команда запускает тот же поиск, что и веб-интерфейс, с ящиком и датой из каждого запроса. Она печатает Recall@K и nDCG@K по размеченным запросам, MRR@K по запросам с одним релевантным письмом и p99 времени вызова поиска без индексации. Флаг `--output` сохраняет по одной строке JSON на запрос с полями `query_id` и `doc_ids` в порядке выдачи.

## Ближайший план команды

1. **ML — разобрать пять промахов BM25.** Начать с запроса про электронные чеки за 1 октября 2028 года. В топ-10 попали 4 из 12 размеченных писем. Для пропущенных писем проверить фильтр даты, совпадения слов и позицию до отсечения выдачи. Причина промаха подскажет, что менять в следующем эксперименте.
2. **Бэкенд и ML — подключить первого кандидата к сервису.** Провести один запрос через UI и бенчмарк с одинаковыми ящиком, датой и K. Сверить последовательность `doc_id`. Затем через тот же интерфейс сравнить BM25, энкодер и гибрид.
3. **Продакт — проверить поиск своими словами.** До выбора модели подготовить перефразировки и вручную проверить, какие письма отвечают каждой из них. Отложить примеры до финального сравнения и отдельно показать результат на новых формулировках.
4. **UI — показать, как поиск понял дату.** Для запроса «чеки за вчера» вывести рядом с результатами вычисленный календарный день. Кандидат для бонусного трека — подборка выбранных чеков за день, которую можно открыть повторно.
