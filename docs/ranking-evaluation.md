# Проверка ранжирования писем

Эксперимент запускается отдельным пакетом `vk_mail_search` на корпусе из этого репозитория. [Сохранённые выдачи, разбор промахов и метрики](../benchmarks/period_ranking/results/)

## Воспроизведение baseline

Замер сделан на `057e699f7c775e529de31f862b772a896e2be2f4` исходного репозитория. SHA-256 архива организаторов — `2df885f77be8f8aa750b484439fc99dfc2a401fce53306160c03ad95cae0de03`. На 99 запросах Recall@10 **0,893223**, nDCG@10 **0,923932**, MRR@10 **0,921717**. Recall@10 совпал с опубликованными 0,8932 при округлении до четырёх знаков. [Замер команды](https://github.com/ttm545/b2baihacatondamirhuesos/blob/057e699f7c775e529de31f862b772a896e2be2f4/docs/decisions.md)

| Выборка | Запросы | Recall@10 | Recall@20 | nDCG@10 | nDCG@20 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Все публичные | 99 | 0,893223 | 0,953298 | 0,923932 | 0,937460 |
| В ящике и дне есть размеченные релевантные и остальные письма | 50 | 0,841722 | 0,944580 | 0,849386 | 0,876171 |

Парсер выделил ожидаемые день и тему во всех 99 запросах. Топ-10 потерял 231 размеченное письмо на 21 запросе. Превышение K объясняет 196 потерь, посторонние письма заняли 35 потенциально релевантных позиций. У 32 из этих 35 пропусков был ненулевой BM25, у трёх отсутствовало лексическое совпадение. На 11 запросах 20 из 35 писем нашлись на позициях 11–20. Остальные 15 были ниже 20-й позиции. Из 121 письма за границей топ-20 минимум 104 не могли войти из-за числа релевантных писем.

| Запрос | Пропуск | Что оказалось выше |

| `H-4519ace06f566a9f1637`, выгрузка контейнеров | `L-f8c64820792ebfeb44bc`, место 34, оценка 0 | Слитное «ГрузоперевозкиВыгрузка» и «контейнерSYN» не совпали с токенами запроса. Выше досмотр `L-42c39168fe1de2e7dc06` и прибытие автомашины `L-09bf08ef003d7715287d`. |
| `H-858ce7fee338506cefbe`, отклонённые платежи | `L-12701ff34c88f3577a21`, место 11 | Выше три подтверждения успешной оплаты, в том числе `L-be503df04d0dc85f0738`. |

В отчёте JSON для каждого промаха есть `doc_id`, полный ранг, признак попадания в топ-20, оценка, причина и список вышестоящих писем без положительной оценки. Категория `limit_at_10` означает, что выше конкретного письма уже стоят как минимум десять релевантных. Файл выдачи содержит топ-20 для всех 99 запросов.

```sh
python -m venv .artifacts/period-ranking/env
source .artifacts/period-ranking/env/bin/activate
export VK_DATA_DIR="$PWD/mipt_mail_search_participants"
export VK_CACHE_DIR="$PWD/.artifacts/period-ranking/cache"

python -m vk_mail_search.evaluate --searcher dated:bm25 --k 20 \
  --out runs/period-ranking/predictions-baseline.jsonl > runs/period-ranking/baseline.json
python -m vk_mail_search.analyze_dated --pred runs/period-ranking/predictions-baseline.jsonl \
  --out runs/period-ranking/baseline-misses.json
python -m unittest discover -s benchmarks/period_ranking/checks -p 'check_*.py'
```

## Условия эксперимента

В отложенном наборе по 10 перефразировок, запросов без даты и запросов на близкие события. Периоды датированных запросов взяты из дней, отсутствующих в публичной разметке соответствующего ящика. Для них проверяли письма всего дня. Для запросов без даты проверяли ящик целиком по признакам события и читали найденные письма, включая письма без известного дня получения. В пяти запросах без даты положительные примеры есть за несколько дней. Разметка бинарная и зафиксирована перед замером. [Запросы, критерии и doc_id](../benchmarks/mail_ranking_holdout.jsonl)

Для всех вариантов действуют один ящик, одна дата отсечения, один парсер и приоритет писем периода. Оценки BM25 используют статистику ящика. В варианте с темой вклад терма умножается на два при совпадении с леммой в явном заголовке `Тема` или `Subject`. USER2-base использует прежнюю ревизию весов и прежние фрагменты. В сравнительном RRF веса обеих веток равны, глубина покрывает весь набор допустимых кандидатов. Нулевое совпадение BM25 не получает голоса в RRF.

В парном эксперименте `dated:hybrid` и `dated-period:hybrid` используют одну конфигурацию RRF и одинаковые ветки. Второй вариант сливает полные ранги внутри периода, а для добора за его пределами использует исходное слияние топ-100. Запрос без периода идёт в исходный гибрид. Метрики сравнения порядка отбора считаются по запросам с точным совпадением распознанного периода и известного дня получения.

```sh
python -m pip install -r benchmarks/period_ranking/requirements-embeddings.txt
python -m vk_mail_search.benchmark_ranking --out runs/period-ranking compare
```

Команда пишет выдачу топ-20 и отчёт по каждому варианту, включая p99 синхронного вызова `search` при K=20 после 10 прогревов. `comparison.json` также содержит смену ранга писем периода, которые получили нулевую оценку в исходном гибриде.

## Результаты сравнения

Замеры сделаны последовательно на одном MacBook Air M3, 16 ГБ, Python 3.12.14, Torch 2.15.0, USER2-base на MPS. Индекс и модель загружены до замера. p99 вызова поиска рассчитан по 129 запросам при K=20 без HTTP. SHA-256 отложенной разметки — `f797b19712d73daa1e5d3e8358153e7a53aad019c87f83f453f17120273a4dcc`.

Recall@10 и nDCG@10 пересчитаны по первым десяти письмам из сохранённой выдачи каждого запуска.

| Вариант | Публичные Recall@10 / nDCG@10 | Публичный Recall@20 | Ручные Recall@10 / nDCG@10 | Ручной Recall@20 | p99 поиска, мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | **0,893223** / 0,923932 | 0,953298 | 0,762129 / 0,802192 | 0,837297 | 1,850 |
| BM25 ×2 по теме | 0,890751 / 0,936245 | **0,954905** | **0,818824** / 0,837589 | **0,898409** | 1,755 |
| USER2-base | 0,878346 / 0,924486 | 0,924712 | 0,736200 / 0,826160 | 0,823100 | 43,448 |
| RRF BM25 ×2 + USER2-base | 0,890640 / **0,949930** | 0,940206 | 0,782624 / **0,878184** | 0,853406 | 42,933 |

| Вариант | Перефразировки, Recall@10 / nDCG@10 | Без даты, Recall@10 / nDCG@10 | Близкие события, Recall@10 / nDCG@10 |
| --- | ---: | ---: | ---: |
| BM25 | 1,000000 / 0,882320 | 0,625534 / 0,612978 | 0,660853 / 0,911278 |
| BM25 ×2 по теме | 1,000000 / 0,882320 | **0,795620** / 0,719168 | 0,660853 / 0,911278 |
| USER2-base | 1,000000 / **0,950000** | 0,555609 / 0,562373 | 0,652992 / 0,966108 |
| RRF BM25 ×2 + USER2-base | 1,000000 / 0,910922 | 0,685791 / **0,749341** | **0,662083** / **0,974288** |

| Порядок обычного RRF | Recall@10 / nDCG@10 на 119 запросах с подтверждённым днём | Recall@20 на тех же запросах | p99 поиска по 129 запросам, мс |
| --- | ---: | ---: | ---: |
| Топ-100 по ящику до выделения периода | 0,876552 / 0,935149 | 0,927734 | 41,696 |
| Полные ранги внутри периода до слияния | 0,878506 / 0,945243 | 0,935022 | 45,479 |

В парном эксперименте 345 релевантных пар на 36 запросах получили ненулевую оценку после смены порядка. Среди них 40 вошли в топ-10, 73 — в топ-20 с позиций ниже соответствующего порога. Например, `L-0a1f3c27533663d02037` поднялось с 80-го на 7-е место в запросе `H-6f1839b2094abab2d9d7` об отклонённых платежах. Проверка выдач подтвердила исходный порядок добора вне периода на 119 запросах и совпадение выдачи на всех 10 запросах без даты.

Для API выбран `dated-period:hybrid-subject` по приоритету nDCG@10. По сравнению с BM25 ×2 он добавил 0,013685 nDCG@10 на публичных запросах и 0,040595 на ручных. Потеря Recall@20 составила 0,014699 и 0,045003 соответственно. На ручных запросах USER2-base дал наибольший эффект для перефразировок, а RRF помог на близких событиях и запросах без даты.

При выбранном RRF на 9 из 99 публичных запросов в позициях 11–20 ещё есть релевантные письма, которые могли бы занять место посторонних в топ-10. Среди 10 запросов на близкие события найдены два таких случая с подтверждённым письмом противоположного типа выше. RRF оставили последним этапом ранжирования. Отложенный набор мал, поэтому эти два примера дают основания для дальнейшего разбора конкретных событий.

## Проверка API

Для воспроизведения HTTP-замера используется API исходного прототипа, подключённый к экспериментальной фабрике поиска. [Коммит API](https://github.com/ttm545/b2baihacatondamirhuesos/commit/20b0fdc54ea5a8fa5a344c3b0076aae438fae2f0)

| Локальный Uvicorn, один процесс | Вызовы при K=20 | Серверный p99, мс | Полный HTTP p99, мс |
| --- | ---: | ---: | ---: |
| Последовательно | 387 | **46,404** | 47,402 |
| 4 параллельных клиента | 387 | **146,653** | 147,940 |

Лимит серверного p99 < 1 с выполнен в обоих прогонах. Все 774 ответа совпали с сохранённым топ-20. Серверный тайминг берётся из `took_ms` API, полный HTTP замер идёт до чтения JSON. Замер относится к локальной машине и этому профилю запросов.

```sh
mkdir -p .artifacts/period-ranking/api
git fetch https://github.com/ttm545/b2baihacatondamirhuesos.git 20b0fdc54ea5a8fa5a344c3b0076aae438fae2f0
git archive FETCH_HEAD requirements-api.txt vk_mail_search/api.py vk_mail_search/web \
  | tar -xf - -C .artifacts/period-ranking/api
python -m pip install -r .artifacts/period-ranking/api/requirements-api.txt
export VK_SEARCHER=dated-period:hybrid-subject
python - <<'PY'
from pathlib import Path
import uvicorn
import vk_mail_search

vk_mail_search.__path__.append(str(Path(".artifacts/period-ranking/api/vk_mail_search").resolve()))
uvicorn.run("vk_mail_search.api:app", host="127.0.0.1", port=8875, access_log=False)
PY
```

Во втором терминале активируйте окружение эксперимента и задайте тот же `VK_DATA_DIR`.

```sh
python -m vk_mail_search.benchmark_ranking --out runs/period-ranking/api-check api \
  --url http://127.0.0.1:8875/api/search --searcher dated-period:hybrid-subject \
  --pred benchmarks/period_ranking/results/predictions-dated-period-hybrid-subject.jsonl --concurrency 4
```

Проверка сверяет топ-20 каждого HTTP-ответа с офлайн-выдачей. В отчёте API есть p99 серверного `took_ms` и полный p99 HTTP-вызова. Код возврата при серверном p99 от 1 секунды равен 1.
