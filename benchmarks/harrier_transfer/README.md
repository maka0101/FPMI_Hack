# Автономный ранжировщик писем с Harrier

На 99 публичных запросах гибрид достиг 0,9892 nDCG@10 и 0,9366 Recall@10. Текущий main дал 0,9883 и 0,9354. На 32 отложенных перефразировках с датой гибрид уступил и main, и внешнему ансамблю. Это эксперимент ветки ML.

## Как работает поиск

Для запроса с датой SQLite BM25 и Harrier 270M формируют два списка глубины 50. Объединяем их по reciprocal rank fusion с весами 0,85 и 0,15. Наш дополнительный индекс отдельно считает совпадения в теме, первых 32 токенах и остальном тексте. Для каждого слова берём частоту в теле, ещё раз прибавляем частоту в первых 32 токенах и пятикратную частоту в теме. Вклад слова равен IDF × tf / (tf + 2). Частые русские окончания нормализуются. Поиск ограничен ящиком, включительными границами запроса и доступностью письма на дату поиска.

В варианте по умолчанию `fallback` исходные позиции писем, найденных BM25, закреплены. Остальные места заполняются из объединения полевого списка и Harrier. Благодаря этому письмо может попасть в выдачу по совпадению в теме, даже если BM25 его пропустил. Запрос только с датой возвращает обычный хронологический список. Без даты глубина обеих исходных ветвей увеличивается до 200. Балл равен `0,55 × 61 × RRF + 0,45 × 2^(-возраст_в_днях/30)`. Письмо без известной даты получает нулевую надбавку.

Внешний источник подсказал учитывать поля письма и свежесть. Полевой индекс, подсчёт баллов и объединение списков реализованы в [ranker.py](ranker.py). Веса Harrier, код энкодера, формат индекса, BM25 и календарный парсер происходят из нашего проекта. Параметры свежести взяты из предыдущей сетки на 44 tune. Публичный и отложенный срезы уже использовались командой. Вариант fallback проверялся после того, как на публичном наборе обнаружилась регрессия при полной замене BM25. Эти результаты относятся к известному бенчмарку.

## Парное сравнение

В каждой ячейке указаны **nDCG@10 / Recall@10**. Все три системы получили один и тот же текст, ящик, дату доступности, корпус и разметку. Замер выполнен на штатном [main 0c27fa7](https://github.com/maka0101/FPMI_Hack/tree/0c27fa74cb93cfe00839074321eb3b7081a38a8c) и отдельно запущенном [ансамбле da14429](https://github.com/ttm545/b2baihacatondamirhuesos/tree/da14429dac3083480e4b41b0b301ea4c907fc83b). Ансамбль запрашивался с глубиной 100 с последующим отсечением до десяти.

При полной замене BM25 на наш полевой поиск (`native`) публичные nDCG и Recall падают до 0,9380 / 0,8922. Трёхветочный RRF (`blend`, веса BM25 / Harrier / поля 0,60 / 0,15 / 0,25) даёт 0,9692 / 0,9224. Пересортировка только первой десятки main (`rerank`) даёт 0,9840 / 0,9354. Для сравнения `fresh_only` сохраняет штатный порядок для запросов с датой и применяет бонус свежести без даты. На W3C этот бонус ухудшает поиск конкретного старого письма.

[VK](vk.json), [SARA](sara.json), [Vectrix](vectrix.json) и [W3C](w3c.json) содержат Recall, nDCG и MRR на глубинах 5 и 10 для каждого кандидата. Всего 1 532 выполнения на систему, включая производные формулировки VK и два диагностических среза по 99. На VK без даты и с расширенным периодом сохранена исходная разметка. 32 отложенных запроса относятся к четырём семействам. Внешние данные SARA и W3C восстановлены из открытых источников. W3C включает 125 целей и 8 000 фоновых писем. Поэтому на этих корпусах парные цифры ансамбля (0,0620 и 0,2895 nDCG@10) отличаются от опубликованных автором (0,0565 и 0,2945). ## Повторить из корня ML

Для пересчёта всех метрик достаточно Python 3.11+. В репозитории лежат точные тексты запросов, qrels, два списка кандидатов и контрольные top-10 обеих баз. Для VK полевой индекс при каждом запуске строится заново по исходным письмам. Для трёх внешних наборов все запросы без даты, поэтому для повтора достаточно ID, ящика и даты каждого письма. Тексты внешних писем в слепок не включены.

```sh
python3 -m benchmarks.harrier_transfer.compare --out-dir /tmp/harrier-results
```

Живой поиск по произвольному запросу требует локальных весов Harrier. При первом запуске строится индекс корпуса. Эталонный замер выполнен с torch 2.15.0 и transformers 5.23.0 на MPS. Из корня ML в отдельном окружении:

```sh
python -m pip install -r benchmarks/harrier_transfer/requirements-live.txt
export ARTIFACT_DIR="$PWD/.cache/harrier"
hf download microsoft/harrier-oss-v1-270m --revision 31de22b673913c7d658c0f03f792d77c2dcf8ebd --local-dir "$ARTIFACT_DIR/weights/harrier270" config.json model.safetensors tokenizer.json tokenizer_config.json special_tokens_map.json
python -m benchmarks.harrier_transfer.export search box-2d28af4e4602 2025-10-20 'Покажи вчерашние уведомления о новых заказах'
```

Чтобы получить новый пул VK непосредственно из энкодера и проверить его по контрольным top-10 main, выполните:

```sh
mkdir -p /tmp/harrier-live-pools
python -m benchmarks.harrier_transfer.export rebuild vk /tmp/harrier-live-pools/vk.json.gz
python -m benchmarks.harrier_transfer.compare --corpus vk --fixtures /tmp/harrier-live-pools --out-dir /tmp/harrier-live-results
```

Для внешних корпусов передайте `--data /путь/к/корпусу` перед `rebuild` и соответствующее имя набора. Проверяется SHA-256 файла documents.jsonl. Контрольные top-10 соответствуют зафиксированному прогону. На другом вычислительном устройстве возможны численные расхождения эмбеддингов при почти равных баллах.
